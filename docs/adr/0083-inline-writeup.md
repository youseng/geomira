# ADR-0083 In-place Markdown and math in Write-up

The maintainer wants to write in the typeset solution beside the figure. Geomdraw achieves this by storing a Markdown string, intercepting input and rebuilding a contenteditable surface. Its editing code also translates selections between DOM nodes and source offsets, keeps complete text snapshots for Undo and handles clipboard and composition events. Keeping these details consistent across browsers is a substantial part of an editor.

Use the approved CodeMirror 6 packages for the editable document, selections, clipboard, composition and history. Live and Source share one mounted editor. Live supplies decorations at offsets in the original Markdown. Completed math becomes a KaTeX MathML widget. Entering the formula reveals its source. Heading markers are visible on the active line, and each heading level has a scoped typographic style. Visiting another panel preserves writing history. Opening another document creates a fresh editor bound to that document.

Markdown-it identifies syntax, including code where dollar signs are literal. Formatting runs after changes reach the document store. Each editor reuses unchanged KaTeX results from its previous pass. The existing resource limits and recovery semantics apply. An invalid expression stays editable, a failed formatting pass leaves raw text accessible, and a failed editor-module load falls back to a textarea. The editor loads on first use on the hosted site. The standalone download includes the editor, renderer and dependency notices.

This supersedes ADR-0082's separate preview. That layout used a native textarea but required writers to divide their attention between two views. A hand-built contenteditable would save the CodeMirror bundle cost but would put caret translation, editing history and browser input differences back into Geomira. The write-up browser and unit tests now exercise the new surface, including heading levels, inline editing, Markdown downloads and recovery.
