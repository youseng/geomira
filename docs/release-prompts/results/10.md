## Delivered behavior

- Atomic singleton batches replace title/author/viewport in sequential order, validate any prefix endangered by repeated singleton replacement, map diagnostic columns back to the command and return one edit or no change.
- Accessible native source textarea with line numbers, synchronized scrolling and decorative
  lexer highlighting. Pointer/keyboard diagnostic buttons select UTF-16 source spans.
- Registry-based completion and signature help at the caret, including draft-defined objects
  before the current line. Pointer, keyboard, no-match and dismissal behavior are explicit.
  Comments and strings do not auto-open completion; no GUI Claim action is offered.
- Completion insertion preserves native field Undo/Redo in Text and Command. A direct before
  probe exposed source corruption in Text and a no-op Command undo; both are now covered.
- Explicit safe semicolon-to-lines conversion retains file grammar, quoted strings, nested
  constructs and comments. Source blur applies valid text without silently formatting it;
  explicit Apply/Ctrl+Enter formats, and construction regeneration is explained visibly.
- IME composition holds automatic application until completion. Shared 500 ms applies,
  coalescing, stale drafts and file dialog decisions remain in TextApplier; no second document.
- Existing canonical save/share/export output and inactive claim/assumption data remain intact.

## Command batch performance follow-up

The initial singleton repair re-parsed/evaluated every batch prefix. It now assembles source
and an origin map once, validating a prefix only immediately before overwriting a singleton
already changed in the batch, then validates the final source. This retains the earlier-invalid-
directive guard without making ordinary append-only batches repeatedly evaluate the figure.
All **27 command tests / 4 files passed**, including all prior 26 and a new 120-point batch
whose geometry, canonical text, single history entry and undo match the intended document.
Focused editor lint and typecheck passed.

A diagnostic three-run benchmark of the same valid 120-point batch on this shared host
measured **1349.65 / 866.85 / 786.06 ms before**, versus **191.86 / 91.58 / 45.71 ms after**.
These are observed timings under concurrent work, not a new acceptance threshold or a
portable performance guarantee. The test asserts semantics rather than wall-clock duration
or mocked implementation call counts. The final integrated candidate still needs its full
verification and browser performance runs in isolation.
