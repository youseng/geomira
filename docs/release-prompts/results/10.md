## CI Firefox IME fixture investigation

Run `43831973644`, job `133179204326`, artifact `14209991740` contained one hosted-Firefox
IME assertion failure: the trace showed synthetic compositionstart → Playwright fill →
compositionupdate → Ctrl+Enter → 650 ms → two drawn objects. The archive was downloaded via
the GitHub connector and the failing Firefox trace inspected. The generic CLI artifact/log
redirect returned Forbidden; that was a retrieval limitation, not a test result.

Playwright 1.56.1's Firefox `ffInput.sendText` sends `Page.insertText`; the installed matching
Firefox Juggler `PageAgent._insertText` calls `textInputProcessor().commitCompositionWith(text)`.
Therefore `fill` legitimately commits/ends native composition in this engine. The old fixture
incorrectly asserted that this committed text remained an uncommitted IME draft until a second,
manual compositionend event. No production guard was weakened or changed to satisfy it.

The corrected fixture focuses the field, dispatches compositionstart and a native-value-setter
plus `beforeinput`/`input` with `isComposing: true` to represent intermediate IME text without
instructing Firefox to commit it. It explicitly checks no compositionend occurred, preserves
the one-drawn-object assertion before commit, and dispatches compositionend followed immediately
by the final non-composing input. It then requires the new object, exact source and working
Ctrl+Enter formatting, so completion of composition cannot leave editing stuck.

Focused corrected IME test: **3 passed (13.3 seconds)** across desktop, mobile emulation and
file Chromium; focused ESLint passed. Local Firefox still cannot start (headless/graphics and
sandbox diagnostics), so the corrected Firefox/WebKit results require the integrated CI run.
All original application assertions remain, with additional event-order and resumed-editing
assertions. Production IME code is unchanged by this fixture correction.

## Composed-layout completion caret race

Prompt 09's mobile composition exposed an actual input race before Undo: completing midpoint
then immediately typing `A,B)` produced `M=midpoint(,B)A`. The unconditional completion RAF could
run after the first new key and restore the old insertion offset. A deterministic regression
against the old built app reproduced the same failure with a Greek name: expected
`M=midpoint(ω_1,B)`, received `M=midpoint(,B)ω_1`. Its before-fix trace is retained in scratch at
`/tmp/geomira-caret-before.zip`.

Both entry fields now use one `useCompletionCaret` layout effect. It applies only the matching
committed source before paint; a newer value discards stale placement. No asynchronous RAF
selection reset remains in either completion path, and native insertion/Undo/Redo stays intact.
The new browser regression repeats keyboard and pointer acceptance in Text and Command,
preserves middle-line suffixes/Greek identifiers, and deliberately delivers captured animation
frames only after immediate typing. This is scheduler fault injection; no delay was added to
user typing or relaxed timeout to hide the race.

After the fix, the existing **21 source/IME/native-undo scenarios passed** on the rebuilt
hosted, phone and file-Chromium outputs. The new scheduler regression initially had a fixture
positioning issue in Command (programmatic selection had not yet updated that entry field's
completion cursor). It now positions the caret with native arrow keys and verifies the offered
midpoint choice before acceptance. Immediate post-accept typing remains undelayed. The corrected
repeated regression passed **3/3 (13.5 seconds)** across desktop, phone and file Chromium, testing
both entry fields and keyboard/pointer acceptance twice per case. Focused lint, web typecheck
and both public builds passed. Prompt 09 must rerun the composed workspace scenarios with this
patch; this isolated worktree does not establish final combined layout acceptance.

## Native undo for separator conversion

Root's probe and a new before-fix browser regression confirmed that programmatic conversion
left native Undo unable to restore `A=(0,0); B=(4,0)`. Conversion now reuses the existing native
insertion transaction across the full textarea range before the shared draft follows its value.
Its pointer-down blur prevention is retained. The regression waits for the converted two-point
figure, requires one native Undo to restore the exact original semicolon text, verifies that
invalid source cannot apply or erase the two-point figure after its debounce pause, then requires
Redo to restore the exact separate lines. This is a debounce-safety observation, not a delay
added to conceal an interaction race.

Before fix: **1 desktop failure** at the exact undone-source assertion. After fix: **3 passed
(14.9 seconds)** on desktop, mobile and file Chromium. Focused ESLint, formatting and both public
builds passed. No history/parse assertion, timeout, tolerance or public capability changed.
