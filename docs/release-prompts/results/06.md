## Changes

- Intersection and common-tangent reuse now requires dependency-derived incidence/tangency
  in addition to current coordinates/carriers. Independent coincident objects remain free;
  dependent branches continue following their parents. Existing defining points, equivalent
  constructions and one-undo batching remain supported.
- The narrow `@geomira/discovery/construction` facade exposes existing pure registry facts
  for a construction action. It does not evaluate saved claims/assumptions or run jobs.
- Preselection runs through the real sequential picker: semantic line inputs consume one
  line or two points, partial pairs wait, excessive selections are atomic, and repeated
  steps finish with immediate refusal feedback and retained picks when finishing fails.
- Apply transformation uses its own supported-kind picker for ordinary shapes, conics,
  marks and text. Ideal points work through Objects; no nonexistent canvas shape is added.
  Unsupported conic image sugar remains refused.
- No public claim-testing or discovery surface, capability flag or job path is enabled.

## Regression-first evidence

The corrected initial 12-case API regression run had **9 failures / 3 passes** before the
implementation. It reproduced suppressed dependent tangents/intersections, selected line
pairs (including partial/repeated inputs), lost locked-polygon finish refusal, rejected
conic maps in either order and panel-selected ideal points. An earlier run had one invalid
fixture using numeric layer ID `0`; corrected to the actual `main` layer before recording
this reproduction. Seven ordinary mapped-kind cases and a stored-claim non-interference
case were subsequently added, yielding twenty new API cases total.

The new tests inspect expressions/parent identities, then move a parent and check both
circle tangencies or intersection incidences. They preserve free P/Q, document invariants
and undo/redo behavior, compare `apply(t,k)` with the existing language oracle, and confirm
that stored claims never become identity facts.

## Tests and limitations

New files: `packages/editor/test/tool-dependencies.test.ts` and
`apps/web/e2e/tool-dependencies.spec.ts`. The existing discovery export-surface test receives
only two added lines for the new subpath; no frozen assertion/line is removed or weakened.
All other historical tests, tolerances, count/coverage floors and snapshot references remain
unchanged. SPEC and CHANGELOG record the behavior; integrated STATUS is updated centrally.

Complex dependency equivalences unknown to the conservative construction-fact closure can
produce an extra dependent object. This preserves dependency semantics rather than treating
coincidence as identity. Ideal points remain panel-only because they are not drawn. Physical
devices and real screen readers were not exercised; Firefox/WebKit browser runs are left to
combined supported-environment/CI validation. No browser performance result is inferred from
these loaded functional runs. Full integration verification remains required.
