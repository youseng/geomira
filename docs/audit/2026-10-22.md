## 8. Design smells against SPEC §18: ADR proposals

These were proposals when the audit was written. The maintainer decided P1, P3, P4 and P5 for
this PR and left P2 to audit 2 (§12).

- **P1: a relative test for a map's scale factor.** `similarityProblem` tests a = 0 per
  component as a dimensionless quantity within EPS.
  - h1 = h2 = homothety(O, 1e-5) and h3 = homothety(O, 1e5): `compose(h1, compose(h2, h3))` is a
    transform, but `compose(compose(h1, h2), h3)` is Undefined ("collapses the plane"). Applying
    the three maps one by one is defined.
  - ADR-0007 decision 2 accepts that a composition can collapse in floats. The asymmetry breaks
    associativity, though.
  - Proposal: decide a = 0 relative to the factors' own magnitudes (|a| ≤ EPS·|a₁||a₂|), or carry
    the exact value. Needs an ADR because it changes which transforms are Undefined.
- **P2: chirality of rotated lines.** `mapLine` keeps the input's chirality flag, as SPEC §4 says.
  But `rotate(line, O, θ)` with a literal θ does not commute with mirroring, so for θ ≠ 0°, 180°
  no flag describes the image. For 90° the flag should toggle.
  - Consequence: a claim whose failure depends on such a line can never get ORIENTATION-DEPENDENT
    (L16).
  - Proposal: mark the image of a line under a rotation by a literal angle as orientation-dependent
    (a third flag value, or a rule that the rotation's angle is itself an orientation choice).
- **P3: locked layers.** `Layer.locked` exists in the document and the text, but nothing reads it:
  objects of a locked layer can be dragged, edited and removed. SPEC does not define "locked".
  - Proposal: define it (no drag, no edit, no remove, through the GUI only), or remove the field.
- **P4: freeze test helpers too.** The add-only guard checks only `*.test.ts(x)` and
  `*.spec.ts(x)`. The helpers under `test/` (corpora, degenerate-case tables, L3 plans,
  fuzzers) carry assertions and data the laws depend on.
  - Proposal: extend the guard to every file under `test/` and `e2e/`, except snapshots and
    generated files.
- **P5: give the nightly a later trigger.** No nightly ran on Run 9a or 9b code, so a note quoted a
  score two runs old.
  - Proposal: dispatch the nightly on the merge of each run (`push` to main) as well as on the
    schedule, so STATUS can always cite a nightly of the code it describes.
